# プロダクト説明書：onsite

## 一言で

誰かがその場所に残した投稿を、実際に近づいたときだけひらける、おでかけSNS。

## 誰の、どんな課題か（Why）

- **課題**：SNS で街や旅先の面白い場所を見ても、写真を見た時点で満足してしまい、実際に行くことは少ない。観光情報も「有名な場所」に偏り、地元の人が知っている小さな発見は外に伝わりにくい。
- **対象**：街歩きや旅行が好きな人、知らない街を訪れた観光客、その街の小さな面白さを知っている地元の人、学園祭や商店街のように「回ってほしい場所」がある主催者。

## どう解決するか

- 地図には投稿の **予告だけ** を出す（例：「この角度から見ると鳥に見える建物」）。
- 本文と写真は、投稿者が決めた範囲（100m・300m・500m・1km）に **入った人だけ** がひらける。
- 答えを先に見せないことで、「確かめに行きたい」という出かける理由を作る。
- ひらいた人だけが書ける **寄せ書き** で、同じ場所に来た人どうしがつながる。
- 投稿をつないだ **イベント（巡りルート）** で、ひとつの発見を「街を巡る体験」に広げる。
- 自分の **足あと** と、みんなの **踏み跡** が地図に残り、誰かが歩いた道が次の人の道しるべになる。

## なぜこの方法か（Intent）

- 予告を遠くから見せるのは、目的地を選んで出かけられるようにするため（存在ごと隠すと、どこへ行けばいいか分からず、投稿が少ないうちは何も起きない）。
- 範囲を投稿者が選べるのは、「この角度から」のようにピンポイントの発見と、「この辺りの路地」「この町並み」のように広い発見の両方を扱うため。旅先の大きな名所にも使えるよう 1km まで選べる。
- 寄せ書きをひらいた人だけに限ったのは、「その場所に行った人だけの会話」にすることで、行く理由をもう一つ作るため。荒らしや先読みも防げる。
- イベントは誰でも作れる。主催者だけでなく、「自分のおすすめの回り方」を共有できるようにするため。
- 踏み跡をマス目の回数にしたのは、「みんなが歩いた道」を見せつつ、個人の移動は特定できないようにするため。
- 開封の瞬間はドット絵のゲーム風にした。普段の画面は落ち着いた SNS らしく、歩いてたどり着いた瞬間だけを特別にするため。
- 判定はサーバー（Cloud Functions）で行い、本文・写真・寄せ書きはブラウザから直接読めないようにした。開発者ツールを開いても先に読めない。

## 主な機能

1. 地図上で場所を選び、予告・本文・写真（その場で撮影）・範囲を決めて投稿
2. 地図に予告を、ストーリーのリングのような印で表示（未開封はグラデーション、開封済みはグレー）
3. 現在地との距離を表示し、範囲内に入ると開封（はじめてはドット絵の宝箱の演出）
4. 寄せ書き（コメント）といいね（ひらいた人と投稿者だけ）
5. フィード（まわりの予告が近い順・新着順に重なって流れる）
6. イベント（投稿をつないだ巡りルート、参加、進み具合、制覇の演出）
7. 自分の足あと、みんなの踏み跡
8. おでかけログ（1 日ごとの記録とストーリー形式のふりかえり）
9. プロフィール（経験値とレベル）、お知らせ
10. デモモード（現地に行けない人が、地図をタップして体験できる）
11. PWA と Android アプリ

## 使っている技術

React / Vite / Google Maps JavaScript API / Firebase Authentication / Cloud Firestore / Cloud Storage for Firebase / Cloud Functions for Firebase / Firebase Hosting / Capacitor

## 安全とプライバシー

- 現在地は距離の判定にだけ使い、サーバーには保存しない（開封時の距離だけを本人のログに残す）。
- 投稿の場所は地図上で選ぶ方式にし、現在地にそのまま置こうとすると注意を出す。
- 自分の足あとは端末の中だけに保存する。みんなの踏み跡への共有は初期設定でオフ。
- GPS は偽装できるため、「現地にいた証明」には使わない。
