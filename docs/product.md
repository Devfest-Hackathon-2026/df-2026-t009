# プロダクト説明書：ここだけ（下書き）

## 一言で

誰かがその場所に残した投稿を、実際に近づいたときだけ読める散歩SNS。

## 誰の、どんな課題か（Why）

- **課題**：SNS で街の面白い場所を見ても、写真を見た時点で満足してしまい、実際に行くことは少ない。観光情報も「有名な場所」に偏り、地元の人が知っている小さな発見は外に伝わりにくい。
- **対象**：散歩や街歩きが好きな人、知らない街を訪れた観光客、その街の小さな面白さを知っている地元の人。

## どう解決するか

- 地図には投稿の **予告だけ** を出す（例：「この角度から見ると鳥に見える建物」）。
- 本文と写真は、投稿者が決めた範囲（100m・300m・500m）に **入った人だけ** が読める。
- 答えを先に見せないことで、「確かめに行きたい」という歩く理由を作る。読んだ記録は自分の「散歩ログ」に残る。

## なぜこの方法か（Intent）

- 予告を遠くから見せるのは、目的地を選んで歩けるようにするため（存在ごと隠すと、どこへ行けばいいか分からず、投稿が少ないうちは何も起きない）。
- 範囲を投稿者が選べるのは、「この角度から」のようにピンポイントの発見と、「この辺りの路地」のように広い発見の両方を扱うため。
- 判定はサーバー（Cloud Functions）で行い、本文と写真はブラウザから直接読めないようにした。開発者ツールを開いても先に読めない。

## 主な機能

1. 地図上で場所を選び、予告・本文・写真・範囲を決めて投稿
2. 地図に予告と範囲を表示（未開封・範囲内・開封済み・自分の投稿で色分け）
3. 現在地との距離を表示し、範囲内に入ると開封
4. 散歩ログ（ひらいた投稿・置いた投稿）
5. デモモード（現地に行けない人が、地図をタップして体験できる）

## 使っている技術

React / Vite / Google Maps JavaScript API / Firebase Authentication / Cloud Firestore / Cloud Storage for Firebase / Cloud Functions for Firebase / Firebase Hosting

## 安全とプライバシー

- 現在地は距離の判定にだけ使い、保存・共有しない（開封時の距離だけを本人のログに残す）。
- 投稿の場所は地図上で選ぶ方式にし、現在地にそのまま置こうとすると注意を出す。
- GPS は偽装できるため、「現地にいた証明」には使わない。

## 今後

- 投稿を存在ごと隠す「シークレット投稿」（偶然の発見を楽しむモード）
- 開封した人どうしの「ここで見たよ」スタンプ
- 不適切な投稿の通報と非表示
